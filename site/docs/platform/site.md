`site/` is a Docusaurus 3.10 project (`@platform/site`) with the arcade colour theme (dark by default), the Orama search box, versioning and the two 3D viewers. The docs plugin serves `site/docs` at the site root (`routeBasePath: '/'`) and every `site/versioned_docs/version-<v>` listed in `site/versions.json`.

## Configuration

`site/docusaurus.config.js` hardcodes nothing about identity: `title`, `tagline`, `url`, `baseUrl`, `organizationName`, `projectName`, the navbar title, the footer copyright, the edit URL and the Editor link all come from `platform.config.js`. `features.search` toggles the Orama plugin; `features.editor` toggles the navbar and footer Editor links (an `href` to `pathname:///editor/`). Versions are read from `versions.json` and labelled Latest plus each frozen label. `onBrokenLinks` is `throw`, but `markdown.hooks.onBrokenMarkdownLinks` is `warn`, so a broken route link fails the build while a broken relative `.md` link only warns. The OKF validator (`npm run okf:check`) is the dependable check for broken relative `.md` links.

The docs plugin `exclude` list keeps the OKF reserved files out of the rendered site: `**/AGENTS.md` and `**/README.md`, plus the Docusaurus defaults. Folder `index.md` files render as ordinary pages (hand-written intro plus the generated bullet list), which is what makes the index readable by humans and agents alike. `sidebars.js` is a single autogenerated sidebar over the docs folder, so `sidebar_position` in frontmatter is the only ordering mechanism.

## Prebuild artifacts

`site/scripts/build-platform-artifacts.mjs` runs as `prebuild` and `prestart` and writes to `site/static/platform/` (git-ignored):

- `components.json`: a copy of the hand-maintained `site/components.json` (the editor fetches it from `<baseUrl>platform/components.json`).
- `versions.json`: `{ current: 'Latest', versions: [...] }`.
- `manifest-<version>.json`: a copy of each bundle's `manifest.json` (`current` and every frozen version).
- `search-index-<version>.json`: an Orama index built by `buildSearchIndex` from `@platform/content` over each bundle. No backend reads it yet: `ContentBackend.search` builds its own index in memory.

This script is the `site-scripts` lint element: it may import `@platform/okf-core` and `@platform/content` like the root scripts do.

## Theme, styles and static files

- `site/src/theme/MDXComponents.js` is the global MDX registry: it registers `Tabs`, `TabItem`, `ModelViewer` and `FbxViewer`, so pages need no import lines. The editor relies on this registry: its Markdown rules write these components as plain JSX tags with no import lines. See [Viewers](viewers.md) and [Add a site plugin or viewer](extending/add-site-plugin-or-viewer.md).
- `site/src/css/custom.css` holds the arcade light and dark palette, a few brand rules, the round navbar logo and the navbar GitHub icon. The editor has its own theme module (`services/editor/src/theme/`), so the site needs no editor overrides.
- `site/static/` holds `img`, `models`, `uploads` and the generated, git-ignored `platform` folder.

## Composition root

`site/src/platform/` is the `site-composition` element, the only site code allowed to import service implementations. `createContentBackend()` builds one cached `GithubBrowserBackend` for `organizationName/projectName` with the token from the editor's stored session (`docs-platform.session` in `localStorage`) when present; `defaultRefFor(repo)` looks up `defaultRef` in `codeRepos`; `useAssetUrl` turns a `{ repo, ref, path }` into an object URL through `getAsset`. Everything else under `site/src` sees only `@platform/contracts` and `@platform/viewers`.

## Versioning on the site

A frozen version is a full copy of the bundle under `versioned_docs/version-<v>` with every blob URL and viewer `ref` rewritten to a commit sha, plus `versioned_sidebars/version-<v>-sidebars.json` and an entry in `versions.json`. `docs/versions/<v>.json` records the pins. The generator validates every frozen bundle on each run, so a frozen copy that stops validating fails CI. Version `1.0.0` in this repository is deliberately partial (root index, `systems/index.md`, `systems/inventory.md`) with a README explaining why; see decision 9 in [Decisions](decisions.md).

## Build

`npm run site:build` at the root: build the editor, run the site prebuild and `docusaurus build`, then copy the editor into `site/build/editor/`. `npm run site:start` runs the dev server (prebuild included). Vitest covers the prebuild script (`site/scripts/build-platform-artifacts.test.ts`).
